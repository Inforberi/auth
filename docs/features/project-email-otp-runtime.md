# Проектный вход по email-коду

MP4.1i, 25 октября 2026. Реализация и локальные проверки Luna V1/V2 завершены успешно.

## Решение

Переиспользуется существующая реализация browser email OTP: SQL challenges/outbox, Redis-лимиты, сессии и MFA. Новых зависимостей, таблиц, ENV или публичных маршрутов нет. Восстановление при потере всех факторов остаётся закрытым до готовности проектных prerequisites; обычный TOTP и recovery codes после основного входа используют прежние правила.

`NewProjectEmailOTP` получает доверенный runtime key, общие registry/reader/Redis, SMTP allowlist и конфигурацию. Основной вход (`OTP.Enabled`) и повторная проверка (`OTP.ReauthenticationEnabled`) включаются отдельно. Если оба отключены, зависимости и SMTP не требуются. При включении проверяются конфигурация сессий, timeout и сохранённый SMTP без сетевого подключения.

## Внутренние методы

| Метод | Результат |
| --- | --- |
| `Request` | Запрашивает письмо с одноразовым кодом; возвращает binding и срок действия, сам код не раскрывает. |
| `Confirm` | Потребляет код один раз и создаёт обычную сессию либо возвращает challenge для обязательной MFA. |
| `RequestReauthentication` | Запрашивает отдельный код для допустимой действующей сессии внешнего аккаунта. |
| `ConfirmReauthentication` | Подтверждает управление MFA и меняет токен той же сессии; число сессий не увеличивается. |
| `CompleteMFA` | Завершает существующий TOTP/recovery-code challenge. |
| `StartMFAEnrollment`, `ConfirmMFAEnrollment` | Переиспользуют обязательную установку фактора перед завершением входа. |

Это внутренний assembly API. HTTP, native/JWT и доступность проекта не публикуются этим блоком.

## Гарантии

- Сохраняются существующие условия SQL для активного аккаунта, подтверждённого адреса, credentials, срока/попыток и `auth_version`. Email-код для входа не подтверждает неподтверждённый адрес и не является дополнительным фактором.
- Сохранённая проектная политика `emailotp` проверяется основным входом; переданный caller callback не может её заменить. Reauth имеет собственные правила и не зависит от включения основного email-входа.
- Шифрование и HMAC используют проектный data key и purpose `email-login:v1`; MFA — отдельный `mfa:v1`. Login и reauth также разделены внутри binding/code digest. Redis получает прежние scoped ключи и лимиты.
- Операция занимает один `UsePool`, проверяет актуальность runtime key до и после сценария, не сохраняет pool/service за callback. Финальная проверка не раскрывает результат устаревшего runtime, но не обещает распределённого отката уже зафиксированного действия.
- При требуемой MFA нет обычной сессии до завершения фактора. Отключённый MFA coordinator не разрешает обход включённого у пользователя фактора. Password и email OTP используют общий private coordinator; каждый принимает только свой основной метод входа.
- Зашифрованная OTP-очередь обслуживается тем же ограниченным delivery runner после account/reset. Сохраняются SQL claim/lease, retry и проверка отмены между очередями. Новых workers на проект и неограниченных очередей в памяти нет.

## Проверки

Main выполняет форматирование и просмотр diff. Luna получает immutable snapshot: `task check`, race затронутых пакетов и полный фактический `TestPrepareCommandSQL` на собственных PostgreSQL TLS/SCRAM и Redis.

Добавлены проверки отключённого компонента, привязки MFA к основному методу и SQL/Redis-сценарии: неверный код, успешный вход, replay, metadata сессии, reauth с ротацией, обязательная MFA, отказ без coordinator, сохранённая политика и безопасный повтор доставки без STARTTLS. Локальный SMTP не подтверждает внешнюю доставку. Публичные маршруты, recovery при потере всех факторов, общий fleet budget, GC/RPS и UI остаются отдельными gates.

Luna V2: `task check` exit0, lint0; полный `TestPrepareCommandSQL` exit0 без SKIP, включая email OTP и прежние password/MFA сценарии. Affected race app/auth+cmd — V1 PASS; после него изменены только эквивалентные embedded selectors и synthetic seed. Manifest13 совпал до/после и с рабочим кодом. RedisDB15 пуста, собственные PostgreSQL/Redis containers удалены. Эти результаты не закрывают перечисленные выше публичные и нагрузочные gates.
