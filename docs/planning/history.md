### Результат 5.5d — 10 октября 2026

Реализован защищённый recovery текущего password-профиля: новый purpose-bound токен отправляется только старому verified email после report завершённой смены и привязывается к auth_version блокировки. Recover требует отличающийся новый пароль, возвращает старый адрес входа, снимает verification с остальных contacts, повышает version, отзывает sessions/challenges, инвалидирует все прежние intents/jobs, записывает audit и снимает только защитную блокировку одним commit. Административный повторный block отменяет recovery authority; deleted, stale hash/version, expired/foreign/replayed tokens не допускают восстановления. SQL повторная проверка — transactional freshness, не лишняя HTTP/domain валидация.

Переиспользованы account mail worker и password recovery Redis/global/hash budgets. Добавлены три смысловых production-файла protected_recovery (service/HTTP/SQL), shared hasher mismatch contract, samples EMAIL_CHANGE_RECOVERY_URL/TTL, POST /api/v1/auth/email/change/recover, Swagger; recovery-схема включена в исходную 000001 без отдельной миграции. Миграция проверена up/down/up. Рабочая БД/.env/secrets не менялись, миграции на них не запускались. Временный SQL контейнер и его тестовые данные удалены.

Проверено: task go:fmt, task check (tests + lint, 0 issues), task swagger/check:api, TestPostgresSchema на disposable PostgreSQL 18.6 (прежний набор + recovery purpose/unissued/replay/expiry/version/hash/deleted/contact guards, concurrent consume, admin re-block, audit/outbox rollback, near-protection expiry retention и legacy intent), git diff --check. Реальная почта/browser, Redis fault E2E, нагрузка, CI и full backup drill не запускались. Потерянная старая почта, повторная выдача после expiry/исчерпания delivery, legacy recovery и будущие MFA/OIDC/Telegram-профили не получают автоматический bypass; их операционная политика требует отдельного решения. Далее 5.5e; EMAIL_CHANGE_ENABLED остаётся false в samples, весь 5.5/release не закрыт.

### Архитектура согласована — 7 октября 2026

Пользователь утвердил feature-first дерево с явными domain/service/repository/transport, методами password/emailotp/oidc/telegram и общими account/session/mfa.
