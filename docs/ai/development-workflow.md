# Разработка с AI без лишней работы

Переносимый подход для существующих проектов. Цель — быстрее получать понятные, проверенные изменения; сокращение контекста и расходов не должно ослаблять гарантии. Это правила работы, а не установка плагинов или запуск фоновых задач.

## Один законченный блок

Перед реализацией определить результат, границы, владельцев данных, необходимые гарантии и достаточные проверки. Найти существующий механизм до добавления нового. Не дробить связную операцию на множество задач ради параллельности.

Код — источник фактического поведения; контракт и план — согласованных требований. Хранить одну актуальную заметку о текущей работе, карту первоисточников и подробные результаты проверок отдельно. Не копировать одинаковые статусы в несколько систем памяти.

Для кода использовать определения, ссылки и реализации через Serena/LSP, затем читать нужные тела. Точный текст, SQL и конфигурацию искать через rg. Внешние API сверять по установленной версии и документации. Не перечитывать неизменившиеся файлы и не загружать весь репозиторий по умолчанию.

## Разделение работы

| Исполнитель | Задача |
| --- | --- |
| Основной агент | Контракты, проектирование, реализация, сложные ошибки, итоговая оценка безопасности и результата |
| Обычный процесс или CI | Выполнение заданных formatter/tests/lint и профильных проверок, сохранение логов и exit status |
| Один помощник по необходимости | Ограниченная независимая проверка или разбор сбоя; короткий отчёт с воспроизведением |

Для простого запуска команд отдельная AI-модель не нужна. Более простую модель можно использовать для ограниченного задания, если инструмент действительно позволяет выбрать её. Не обещать доступность модели или экономию без проверки. Дополнительный агент может увеличить суммарные токены; более низкая цена токена не означает меньшее их количество.

Не создавать отдельный чат, автоматизацию, worktree или менять модель без соответствующего разрешения пользователя. Пользоваться уже доступными средствами; отдельный навык нужен только для повторяющегося процесса, который обычные инструкции не покрывают.

## Проверки параллельно с реализацией

1. Назначить одного исполнителя проверок. В этом проекте по выбору пользователя все проверки, включая быстрые целевые, выполняет отдельный чат Luna; основной агент реализует и исправляет код, подготавливает formatter/generated artifacts и неизменяемый снимок. Проверку результата и работу со стендом выполняет Luna. Не дублировать её команды в основном чате.
2. Долгую проверку можно запустить в фоне. Для параллельных правок проверять неизменяемый снимок в отдельном checkout/worktree, включая все предназначенные для проверки изменения. Не коммитить ради снимка без разрешения.
3. В отчёте указать commit и, если есть незакоммиченные изменения, идентификатор патча/снимка, команды, окружение, PASS/FAIL/NOT RUN и путь к логам. Результат относится только к этому коду; skipped не означает PASS.
4. Пока идёт проверка, продолжать только независимую работу. Авторизация, отзыв, изоляция и миграции должны пройти свои проверки до признания соответствующего блока готовым. Зависимую работу не строить на непроверенной гарантии.
5. Общие БД, порты и стенды тоже могут конфликтовать при разных worktree. Изолировать данные и ресурсы, ограничивать параллельность с учётом CPU, памяти и общего бюджета подключений.
6. После правки повторять затронутые проверки. Изменение общих гарантий требует расширения набора; несвязанные успешные проверки не повторять без причины. Проверка старого снимка не подтверждает новый diff.

В основной контекст возвращать только ошибки/блокировки с командой, местом сбоя и диагностикой. Успех подтверждать одной строкой PASS с идентификатором снимка; подробные результаты, команды и exit statuses хранить в evidence/логах. Молчание и завершение процесса сами по себе не означают PASS. Успешные логи не передавать целиком в контекст. Сохранять полную диагностику ошибок и реальный exit status; компактный вывод не должен скрывать сбой. Фоновый запуск не гарантирует работу после остановки приложения или компьютера — это зависит от исполнителя.

## Если проверка нашла проблему

| Ситуация | Действие |
| --- | --- |
| Ошибка реализации | Помощник возвращает команду, воспроизведение и диагностику; основной агент исправляет причину и оценивает влияние |
| Недоступное окружение | Указать NOT RUN/ограничение, восстановить разрешённый стенд; не переписывать корректный код ради отсутствующего сервиса |
| Подозрение на нестабильный тест | Сохранить первый сбой, воспроизвести и разобрать; успешный повтор сам по себе не закрывает проблему |
| Ошибка безопасности или контракта | Остановить зависимую работу и устранить проблему до продолжения |
| Помощник не уверен | Вернуть вопрос и факты основному агенту, не угадывать результат |

По умолчанию помощник не исправляет код: это исключает конфликтующие правки. При отдельном поручении на исправление выделить ему собственный scope и checkout; после интеграции проверить итоговый код. Независимая проверка дополняет тесты, а не заменяет их.

## Когда добавлять инструмент

| Наблюдаемая проблема | Что рассмотреть |
| --- | --- |
| Нужные решения трудно найти в большом объёме документации | RAG с путями/версиями источников, обновлением изменённых документов и проверкой первоисточника перед критичной правкой |
| Требования теряются между разработчиками или агентами | OpenSpec или другой единый процесс спецификаций, заменяющий дублирующиеся планы |
| Регулярно повторяется ручное действие | Существующая команда runner/CI; затем минимальная автоматизация, если она приносит пользу |
| Найден измеренный bottleneck | Профили CPU/heap/SQL, benchmarks, сравнение до/после; PGO — при наличии представительной нагрузки |

RAG дополняет семантический поиск кода; релевантный фрагмент не доказывает полноту влияния изменения. Не индексировать реальные env, secrets, дампы и пользовательские данные. Историю явно отделять от актуальных контрактов. Дополнительный индекс должен оставаться актуальным и окупать своё обслуживание.

Не ставить несколько AI-клиентов, MCP или анализаторов с одинаковой функцией без конкретной потребности. Подключение нового инструмента и зависимостей согласовывать по правилам проекта. Плагин сам по себе не устраняет лишние чтения, проверки или архитектурную сложность.

## Как оценить пользу

На нескольких сопоставимых задачах сравнить время до проверенного результата, ожидание проверок, повторные прогоны, переделки и найденные после завершения ошибки. Токены и стоимость сравнивать только при доступных фактических измерениях, отдельно для всех агентов. Отделять время команды от времени чтения и разбора её результата.

Параллельность может уменьшить ожидание, а точная навигация — лишнее чтение. Процент ускорения заранее неизвестен. Проверки конкурируют за ресурсы и иногда эффективнее выполняются последовательно. Производительность разработки и RPS/память самого сервиса — разные показатели; второй подтверждается отдельными измерениями.

## Перенос в другой проект

Скопировать этот документ, связать с AGENTS.md и указать местные карту, текущую заметку, команды проверок и правила работы со стендом. Не переносить Auth-специфичные команды или обязательные инструменты в проект с другим стеком.

Минимальное правило для AGENTS.md:

```text
Работать небольшими законченными блоками с явными контрактами и проверками.
Искать определения и связи, затем читать нужный код; не перечитывать неизменившееся.
Тесты выполнять обычным процессом; помощника привлекать для конкретной проверки.
Параллельно продолжать только независимую работу, проверяя отдельный снимок кода.
Сохранять команды, версию кода, exit status, диагностику и ограничения проверки.
Повторять затронутые проверки после правок; общие гарантии проверять шире.
Не ослаблять безопасность и качество ради скорости или экономии контекста.
Новые инструменты добавлять под наблюдаемую проблему, пользу подтверждать измерениями.
```

В этом репозитории набор обязательных проверок определён в [implementation](../planning/implementation.md#режим-проверок-после-уточнения-пользователя), навигация — в [карте](index.md). Этот документ их дополняет, не отменяет gates и не запускает отдельную задачу автоматически.
